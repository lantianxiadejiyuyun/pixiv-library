## 2026-10-18：NAS 内存与存储挂载

- 线上内核日志确认容器达到 1280 MiB 内存上限后杀死 Python 进程；10:18 的记录与当前应用容器 ID、API 重启及并发缩略图请求吻合。之后另一次启动失败中，应用的 CIFS 命名卷变成了普通 `_data` 目录绑定，重启策略变成 `no`。两种故障分开处理，没有通过新建空存储标记掩盖挂载问题。
- 新增下载暂存和缩略图内存回归。验证 64 页、64 MiB 暂存时 Python 跟踪堆峰值低于 8 MiB，每次任务只使用一个临时文件描述符；正常、异常、取消及嵌套上下文均关闭文件。实际队列导入两页正文并核对完整性；损坏页在任何书库文件写入前拒绝，保留文本 BOM 规范化与原页顺序。
- 40 个并发缩略图请求合并为一次生成，等待期间健康检查、列表和已缓存图片仍能响应；验证 EXIF 方向、超大图片缩略图拒绝后仍可读取原图，以及错误后的正常重试。
- Linux/NAS 隔离容器 467 项回归通过，包括数据库导出、队列并发、账号权限、重试、原作品发布日期、收藏、关注作者下载、小说封面和八个工作进程重启。Windows 专项 42 项通过；扩大到 238 项时有 1 项既有并发路径校验失败，与此前记录的 `resolve_asset_path` 失败位置相同，未宣称 Windows 扩大套件全通过。
