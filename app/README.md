# 栖页 App

独立 Flutter 客户端，Material 3 原生界面，跟随系统明暗主题。Android 优先，保留 iOS 工程。无需 WebView，也不内置采集器或数据库；手机连接运行在电脑或 NAS 的栖页服务端。

当前源码版本见 [pubspec.yaml](pubspec.yaml)。支持 Android 7.0 及以上，构建包含 ARM64、ARMv7 和 x86_64；APK、SDK 与发布签名均不纳入 Git，请按下方[构建说明](#构建)生成安装包。后续版本使用同一签名才能覆盖升级。真机安装、摄像头扫码和 iOS 构建尚未验证。

## 使用

1. 手机与服务器在同一局域网，或可通过 HTTPS 访问服务器。
2. 网页「设置 → 手机 App」输入手机能访问的服务器根地址，例如 `http://192.168.1.12:8800`。不要使用电脑上的 `localhost` 或 `127.0.0.1`。
3. 生成二维码，App 点击「扫码绑定服务器」。不能使用相机时，可粘贴网页复制的绑定码。
4. 进入书库，按平台筛选、搜索、查看详情，阅读已保存在服务器的漫画和小说。

二维码有效期 5 分钟，只能绑定一次，生成新码会替换旧码。手机凭据保存在系统安全存储，90 天到期；可在网页撤销设备，或 App「服务器」解除绑定。设备可阅读、保存进度和请求服务端下载正文，不能修改管理员设置或读取平台账号、代理、数据库导出。

当前内容通过网络读取；“请求服务器下载正文”保存到服务器，不等于手机离线保存。小说支持章节、字号与章节内位置恢复，多 P 漫画支持翻页、缩放、页目录，系列支持上下篇顺序阅读。断网保存完整书籍尚未实现。iOS 代码与权限声明已准备，需在 macOS 上使用 Xcode 构建和真机验证。

## 阅读方式与返回位置

已下载的漫画、插画在阅读器右上角「阅读方式」菜单切换横向翻页或竖向瀑布流，并记住选择。瀑布流按保存的页序连续展示完整图片，适应屏幕宽度、保留原始比例，按需加载；失败单页可重试。图片不再覆盖放大镜按钮，双击图片进入全屏查看，可双指缩放，关闭后保留原页码与滚动位置；屏幕阅读器也可直接激活图片的缩放操作。页目录与前后页按钮支持直接跳页，恢复页码及页内滚动比例时无需下载所有前页。混合正文和小说保留原阅读控件。详情页提供封面、资料和阅读入口。[390px 瀑布流阅读预览](../docs/app-comic-flow-preview.png)为合成内容的原生渲染。

小说、文章的段落间距独立于行距，随字号和系统文字缩放增大；保留缩进及原始正文文件。[段落排版预览](../docs/app-paragraph-spacing-preview.png)。

## 我的收藏与浏览历史

作品详情右上角爱心进入收藏与评分，可多选分组并设 1–5 星，0 为未评分。侧边栏「我的收藏」提供全部收藏、未分组和分组入口，默认「想看、在看、已看、推荐」四组；支持自定义、重命名和删除分组。删除分组不取消作品收藏，取消收藏保留独立评分。收藏保存在书库服务器，在 Web 与已绑定设备共享，不修改 Pixiv 等平台的远端收藏。[App 分组预览](../docs/app-favorite-groups-preview.png)。

侧边栏「浏览历史」按最近打开作品排序，每次打开详情记录一次，刷新或返回不重复记同次访问。清空历史需确认，保留作品、收藏和阅读进度。历史与收藏均可结合搜索、平台和类型筛选。

漫画卡片左下显示详情采集时取得的总 P 数和平台提供的收藏人数；Pixiv 保存 total_bookmarks，未返回人数的平台不显示该数字。小说封面单独保存，不作为正文页。服务器自动为有可追溯 Pixiv 来源的小说补全缺失封面，保留已下载正文、人工资料和阅读进度；无来源的本地小说不会按标题匹配。详情 worker 每 60 秒检查，每轮游标扫描最多 200 条记录，最多保留 20 个待执行或执行中的自动任务；失败或平台没有封面时，24 小时后重试。自动任务遵守采集总暂停和详情队列暂停；详情页仍保留手动获取入口。

从详情返回书库、从人物详情返回作品墙时，保留已加载分页、搜索筛选和滚动位置。从阅读器返回不再重新请求作品详情，成功保存的进度直接更新当前作品，再次进入可继续阅读；保存失败的进度不写入本地展示状态。详情下载轮询、AI 汉化完成及主动刷新仍更新对应数据，书库下拉刷新仍从第一页重新获取。

## 标签、作者与 AI 汉化

书库左上角菜单的「搜索标签」进入独立搜索页，支持原始标签与中文译名，点击后按标签 ID 筛选作品。作品详情中的标签也可以直接跳转；「查看同作者作品」按当前平台与已记录的作者名筛选，不会将不同平台的同名作者自动合并。

在网页「设置 → 标题与标签 AI 汉化」选择 Ollama 或兼容 OpenAI 的接口，填写服务地址、模型标识和必要的密钥，保存启用后可先点击「测试汉化」。App 作品详情的汉化按钮经确认后提交后台任务；完成后刷新中文标题和标签，原题仍可查看。译名存入 MySQL 并由各设备共享，原文与中文都能搜索。网页也可每批提交最多 50 部未翻译作品。

模型需自行安装或开通，默认未启用。仅向配置的模型发送标题和标签，不发送图片或正文；服务商拒绝、超时、格式错误不会覆盖原文或已有译名。修改原题后旧译名失效，需重新汉化。当前接口流程使用合成模型响应验证，尚未使用用户实际模型评估翻译质量。

## Pixiv 作者主页与收藏

书库侧边栏「作者与收藏」可以搜索已关注作者，打开我的主页、我的收藏，或粘贴 Pixiv 作者 ID／主页／收藏页链接。作者作品和收藏分别提供插画、漫画、小说分类；本人主页确认后显示私密收藏选项，其他作者仅支持公开收藏。

作品详情中的「Pixiv 作者主页」优先使用来源作者 ID；旧作品缺少 ID 时尝试唯一匹配的已关注作者，否则进入作者搜索，不按重名自动认定身份。「查看同作者作品」仍用于本地书库筛选。

资料和每批目录通过服务器采集队列读取，遵循暂停及随机请求间隔。当前批次先保存基本资料，并将缺失封面排队；正文需在作品详情请求下载。向下滚动自动追加已缓存的目录；缓存用尽且站方仍有下一页时，自动将下一批加入采集队列。每次读取最多 24 部；列表末尾保留手动加载和重试入口。插画与漫画收藏共用远端图像列表，会按真实类型筛选，空批次仍可继续。

重新读取目录时先保留旧成员，完整扫描后才更新目录成员；移出目录不删除本地作品及文件。目录达到末页不等于所有正文已保存。不可访问条目和暂不支持的动图会显示不完整状态。需要先在网页登录 Pixiv；采集暂停时请在网页任务页恢复。

## 导航与搜索

书库、平台、已下载、内容类型、作者与收藏、标签和服务器更新入口集中到左侧抽屉，点击左上角菜单或从屏幕左侧滑入打开。搜索固定在顶部；当前平台／类型／标签／作者筛选显示为可关闭的小标签。加载与失败重试放在列表末尾，保留自动追加和下拉刷新。

侧边栏「已下载」只显示服务器已保存完整正文的内容，排除仅封面、空正文、缺失文件及已知缺页的图像作品。可组合搜索、内容类型与平台筛选；点击「全部书库」退出该分类。此处指服务器保存的文件。

## 在线更新与列表加载

Android App 的「侧边栏 → 服务器与更新 → 客户端更新」显示实际安装版本，点击「检查更新」后可查看新版说明、下载进度并安装。先在网页「设置 → Android 客户端更新」发布正式签名的完整 APK；服务器从安装包读取版本，校验包名和发布证书，只允许递增的 versionCode。安装包保存在现有书库存储，随完整备份保存。

手机只从绑定服务器下载，不跟随重定向；下载后校验大小、SHA-256、包名、版本和已安装应用的签名。下载失败清理半成品，原应用及绑定资料保留。Android 8 及以上首次安装可能需要允许栖页安装应用，授权返回后再点击「安装更新」，最终由系统安装界面确认。普通应用不能静默更新。iOS 不使用 APK 更新。

首次需手动安装构建的 APK，此后可在 App 内安装服务器发布的新版。新版本必须使用原签名，并增加 `pubspec.yaml` 的构建号（versionCode）。自行签名构建时，在服务端设置 `LIBRARY_ANDROID_CERT_SHA256` 为自己的证书指纹；不同签名不能覆盖已有应用。旧版若没有更新入口，也需手动安装。

书库、标签、作者列表、作者作品与收藏支持滚动到底部自动追加，顶部下拉重新读取第一页；搜索和切换分类会重置列表。请求中不重复加载，失败保留已读列表并提供重试，到末页停止。远端目录采集仍遵守服务器队列的暂停和随机间隔；下拉读取缓存，作者页的「重新获取」用于重新向站方同步。

APK 检查及下载经过自动化测试，原生安装桥已编译通过；Android 系统安装及不同品牌的权限页面仍需真机验证。实现参考 [Android apksigner](https://developer.android.com/tools/apksigner)、[FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider) 和 [PackageManager](https://developer.android.com/reference/android/content/pm/PackageManager)。

## Pixiv 下载账号

服务器支持主账号检索、多个副账号按功能分工。在网页「账号管理」配置下载、解析详情、检查作者等角色与每账号并发后，App 的目录读取和下载请求自动遵守服务器分工。Pixiv 下载在同一个后台任务获取详情与正文。副账号无法访问的作品会显示下载失败，不自动改用主账号；已有封面和资料保留。

## 构建

需要 Flutter、JDK 17 和 Android SDK（API 36、Build Tools 36、对应 Flutter NDK、SDK CMake 3.22.1）。已验证的工具链为 Flutter 3.47.7、Dart 3.13.5 和 JDK 17。先按官方说明安装工具链并配置 PATH、Android SDK 路径，执行 `flutter doctor` 检查；首次安装 Android SDK 需要接受 Google SDK 许可。仓库不包含本机工具链或环境加载脚本。

正式 APK 使用独立 release 签名。先创建并妥善保存自己的 Android 发布密钥，然后新建 `app/android/key.properties`；以下路径与密码须替换为自己的值，文件与密钥均不提交 Git：

```properties
storeFile=E:/path/to/qiye-release.jks
storePassword=YOUR_PRIVATE_PASSWORD
keyAlias=qiye-release
keyPassword=YOUR_PRIVATE_PASSWORD
```

从项目根目录执行：

```sh
cd app
flutter pub get
flutter analyze
flutter test
flutter build apk --release
```

APK 输出为 `app/build/app/outputs/flutter-apk/app-release.apk`。**单独备份签名与密码**，后续安装包必须使用相同签名才能覆盖升级。发布到服务端前，设置 `LIBRARY_ANDROID_CERT_SHA256` 为该签名证书的 SHA-256 指纹。

Windows 的 Pub 缓存与项目可能位于不同磁盘，工程关闭 Kotlin 增量缓存以支持该布局。若系统同时安装其他 CMake，应在本机 `app/android/local.properties` 配置 SDK 的 CMake 路径，避免误用 MinGW CMake；该文件不提交 Git。

局域网 HTTP 在 Android Manifest 中开放，但客户端只接受私网 IP、回环 IP 或明确局域网主机名的 HTTP 地址；公网要求 HTTPS。所有资源请求必须同源且位于 `/api/`，禁止跟随重定向，不绕过证书检查，不把访问令牌放进 URL。Android 扫码使用随包携带的 ML Kit，无需首次扫码再下载识别组件。

参考：[Flutter Android 配置](https://docs.flutter.dev/platform-integration/android/setup)、[mobile_scanner](https://pub.dev/packages/mobile_scanner)、[系统安全存储](https://pub.dev/packages/flutter_secure_storage)。

## 人物作品墙

侧边栏进入人物作品墙，按人物名／别名、平台、已下载筛选并滚动加载。人物详情显示服务器保存的介绍、别名、原作与来源，以及该人物在书库中的作品，点击作品沿用漫画／小说阅读。联网查询后需明确确认人物候选才会保存资料；服务器缓存资料不会自动触发外网查询，也不等于手机离线缓存。
